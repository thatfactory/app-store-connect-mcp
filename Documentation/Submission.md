# Release readiness and review submission

`check_release_readiness` selects an existing build by exact ID and verifies that it belongs to the configured app, `MAC_OS` platform, and marketing version. It reports each check as `verified`, `blocked`, `manualVerificationRequired`, or `notApplicable`. The check covers the selected repository, editable version state, processed and unexpired build, declared localizations, exact managed metadata, complete ordered `APP_DESKTOP` screenshot bytes, secret-safe review-detail equality, current managed price, configured availability, distribution restrictions, existing review submissions, and release behavior. An availability difference that this MCP reports as `manualActionRequired` blocks submission until the owner applies it in App Store Connect and a fresh read proves agreement.

Privacy declarations, age rating, agreements, trader and regional obligations remain manual because the audited v1 routes do not provide enough evidence to prove them complete. Export compliance is verified only when the exact build explicitly reports that it does not use non-exempt encryption. A successful readiness result cannot guarantee Apple review acceptance.

`plan_submission` requires all four manual confirmations and creates an immutable plan for the exact build. It can select that build, create a compatible review-submission draft, create the exact version item, and submit the draft. It reuses only an existing `READY_FOR_REVIEW` draft item. Another active submission, multiple drafts, unrelated or non-ready draft items, unknown states, or unresolved issues stop the plan. The plan summary distinguishes manual release, automatic release after approval, and scheduled release with its earliest date; unknown behavior blocks submission.

`submit_for_review` is the sole execution path. Start the server with both `--allow-writes` and `--allow-submission`, then provide the fresh plan ID, exact digest, every operation ID, and `authorization.confirmedByHost=true`. `apply_plan` always rejects submission operations. A timeout or lost response triggers readback; no submission write is replayed. Public release, cancellation, rejection workflows, archive upload, and TestFlight management are outside v1.
