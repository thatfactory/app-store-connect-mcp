# Explicit localized metadata synchronization

`plan_metadata_changes` requires an exact AppStore root, platform directory, version string, selected locales and selected domains. The app manifest must contain an existing verified appStoreId/bundleId pair. Ordinary `apply_plan` executes only the approved operation subset through the shared engine.

`appInfo` manages name, subtitle and privacy URL independently from `versionMetadata`, which manages description, keywords, support/marketing URLs and optional promotional/update text. Existing locales and omitted fields are preserved. New AppInfo localizations require their own explicit name. Defaults only fill absent local fields; explicit null or empty values are never replaced by defaults. The server does not translate, truncate or rewrite source prose.

`version` is an explicitly selected shared domain for copyright and release behavior. An absent version additionally requires that domain, an explicit releaseType and no conflicting nonreleased version for its platform. Exact existing versions must be editable. Initial releases use description text; update notes are accepted only when a prior platform version is released. Readiness requirements beyond API creation are handled separately.

Category changes additionally require `manageCategories: true`, even when appInfo is selected. Categories are matched to Apple's top-level catalog for the selected platform. Unsupported null category clearing and parent changes that would clear unmanaged subcategories require manual action. No category is inferred from localized text.

Review details are another explicit shared domain. Environment references remain field-allowlisted. Desired and remote review values are compared using process-keyed hashes; approved execution resolves source values again for the request. Neither the immutable plan nor the journal stores contact/demo secrets or review notes. Changing a referenced secret invalidates the plan. If Apple does not return a verifiable review value, the result remains uncertain rather than claiming success.

Locale-only plans never call screenshot, review, pricing, availability or submission endpoints. They preserve the version's copyright/release fields and categories. Readback covers both locale families independently. API validation results return only fixed recognized codes and field names; response titles/details and arbitrary pointers that could echo secrets are discarded.

A resource that appears or changes identity after planning is not silently patched. Live Headroom acceptance observed Apple creating an empty version-localization companion during AppInfo localization creation. Paired plans explicitly disclose this effect and depend on the approved AppInfo operation; they may populate only an empty companion under the verified parent. Unexpected nonempty content requires a new plan, never an unapproved overwrite. Both independent creation and this observed initialization behavior are tested. If Apple initializes additional resources during version creation, inspect the partial journal and replan from the new state. A timeout after POST is reconciled with reads, not another POST. This adapter does not claim distributed atomicity or global rollback.
