# Screenshot validation and transfer

Phase 07 supplies offline image validation and an internal upload lifecycle. The public approved screenshot planner is described in Screenshot-Sync.md. Tests use synthetic images and mock Apple responses. Live macOS screenshot dogfooding also verified Apple’s object-storage host family and readback of a completed upload with the original MD5.

Original PNG/JPEG bytes are capped at 32 MiB per file and decoded with Apple's ImageIO through the packaged Swift helper on macOS. The helper requires an installed Apple Swift toolchain. PNG chunk boundaries and CRCs are checked before decoding. Accepted APP_DESKTOP sizes are 1280×800, 1440×900, 2560×1600 and 2880×1800, with RGB color, no alpha and no orientation transform. Validation never edits, crops or recompresses the source. SHA-256 binds local bytes; Apple's sourceFileChecksum uses a separate MD5 digest.

Reservation targets must be exact APP_DESKTOP sets with fewer than ten members. A flushed journal records a random UUID filename marker before the single reservation POST. That unique marker supports reconciling an uncertain reservation; filenames alone never establish completed byte identity. The original source name is retained locally. Unresolved reservations remain visible, and read-only reconciliation cannot replay POST or resume byte transfers.

Upload operations must cover the entire source exactly once, with no overlaps or gaps, in at most 100 bounded PUT parts. Execution preserves Apple's returned operation order and headers after rejecting credential-bearing, routing and unsafe transport headers. Every part and the final commit recheck the approved source bytes. Network, 429 and server failures allow bounded retries of the same PUT bytes; expired URLs are not retried. Commit is sent once, only after all parts finish, with uploaded=true and the MD5 checksum.

The asset client is independent of the JWT client. HTTPS storage URLs are limited to Apple's audited `blobstore.apple.com` family from the [asset-upload guidance](https://developer.apple.com/documentation/appstoreconnectapi/uploading-assets-to-app-store-connect) and the `object-storage.apple.com` family observed in a live App Store Connect screenshot reservation. Other storage families require an explicit contract audit. All DNS answers must be public; the selected address is pinned to the HTTPS connection while normal hostname certificate validation remains enabled. Redirects are rejected. The exclusions track [IANA IPv4](https://www.iana.org/assignments/iana-ipv4-special-registry) and [IPv6 special-purpose ranges](https://www.iana.org/assignments/iana-ipv6-special-registry). Storage requests have a 30-second deadline, and signed URLs/header values never enter journals or public results.

Readback verifies exact resource identity, parent membership, processing state and checksum. A COMPLETE response with an absent source checksum remains processing while bounded read-only polling continues; only a present, different checksum is checksumMismatch. A later read can verify the checksum without replaying reservation, transfer or commit. Expiration of the time or read-count polling budget reports screenshotProcessingPending; only cancellation by the caller reports cancelled. Bounded polling returns processing while Apple is pending, and exposes only recognized diagnostic codes on failure. Uncertain commit outcomes use reads, never replay. Cancellation stops future local work and retains reservation IDs; it does not imply remote rollback or delete existing screenshots. Recovery after partial byte transfer requires an explicit fresh decision; this layer does not silently reserve another resource.
