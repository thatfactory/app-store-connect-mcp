# Approved screenshot synchronization

`plan_screenshot_changes` accepts an absolute AppStore root, platform `macOS`, an exact existing version and selected declared locales. Each locale needs an existing version localization; synchronize metadata first if one is absent. Only explicitly present APP_DESKTOP arrays are managed. Genuine source files must pass native image validation. Use `apply_plan` with the exact reviewed operation subset and the independent host authorization assertion.

Each destination owns its own set and screenshot IDs. The planner compares COMPLETE processing state, source MD5 and file size; filenames and lost local caches do not establish equivalence. SHA-256 binds the approved local source, and the upload receipt preserves both hashes and the created ID. Repeated source bytes within a set and ambiguous multiple matching remote images require an explicit cleanup decision. No global image library or cross-parent screenshot-ID reuse is assumed.

A merge plan places the requested images first, then preserves other verified existing images in their prior order. Pending or checksum-less existing images block merge until their recovery is resolved; the tool does not accumulate duplicate reservations. A replace plan shows every deletion and establishes the exact requested array. Missing manifests are unmanaged. An explicit empty replace clears the selected set; an absent empty set requires no creation. Sources shared across languages or versions must be expressly referenced in each manifest.

The complete final order appears in the plan. Reordering alone transfers no bytes. Whenever capacity allows, uploads finish before obsolete images are deleted. At the ten-image limit, the plan shows necessary early removals and their temporary gaps. Replacement is not atomic, and removed images cannot be restored without original bytes. Dependencies prevent later removals and ordering after a failed upload.

Every operation rechecks local inputs and live state immediately before dispatch. Readback verifies parent membership, ordering and processing, including preservation of other images in the same set. Set-creation uncertainty is reconciled through the unique empty destination set, without replay. Upload receipts retain reservation IDs, and operation-status polling performs reads only. A completed upload becomes a checksum-based no-op on a fresh plan; incomplete uploads require reconciliation or an explicit replacement decision. Journals never promise automatic rollback.

Automated coverage uses synthetic originals and mocked Apple APIs, including source changes, wrong parents, partial transfer, uncertain set creation, explicit deletion, and a second no-op plan. Use genuine localized originals for live synchronization; synthetic marketing assets are test fixtures only.
