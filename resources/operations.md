# App Store Connect MCP

Release candidate `0.2.0`: check_release_readiness reports evidence for one exact existing processed build plus synchronized local metadata, screenshot bytes/order, review, commerce and submission state. Privacy, age rating, agreements, export compliance and regional obligations stay explicit when audited API evidence is insufficient. plan_submission creates only submission operations and prominently reports automatic-release behavior. submit_for_review is isolated behind both --allow-writes and --allow-submission, requires the complete exact plan and explicit host confirmation, and is the only route that can execute submission operations. Ordinary apply_plan rejects them. Compatible drafts are reused; unrelated items and conflicting submissions block planning. Uncertain writes are read back and never replayed. Passing readiness cannot guarantee Apple review acceptance. Publication and live destructive acceptance remain separately owner controlled.

TestFlight configuration uses apply_plan for external group creation with enrollment disabled and explicit beta metadata. Use plan_testflight_distribution and apply_testflight_distribution for exact iOS and tvOS build attachment, build-wide notification settings, beta review, notification and separately scoped group public link changes. The beta executor needs both --allow-writes and --allow-beta-distribution and requires the current plan, digest, operation IDs and host confirmation. get_testflight_state reports membership, review and availability separately. Request an enabled group’s join URL explicitly with get_testflight_join_link.

Configure explicit --allowed-root paths for local data access. --allow-writes and --allow-submission are independent operator gates; neither implies a reviewed operation. No repository .env is loaded. Omission means unmanaged. Never share API keys, signed URLs or review contacts through logs.
