# App Store Connect MCP

Readiness and submission build: check_release_readiness reports evidence for one exact existing processed build plus local metadata, screenshot, review, commerce and submission state. Privacy, age rating, agreements, export compliance and regional obligations stay explicit when the audited API evidence is insufficient. plan_submission creates only submission operations and prominently reports automatic-release behavior. submit_for_review is isolated behind both --allow-writes and --allow-submission, requires the complete exact plan and explicit host confirmation, and is the only route that can execute submission operations. Ordinary apply_plan rejects them. Compatible drafts are reused; unrelated items and conflicting submissions block planning. Uncertain writes are read back and never replayed. Passing readiness cannot guarantee Apple review acceptance.

Configure explicit --allowed-root paths for local data access. --allow-writes and --allow-submission are independent operator gates; neither implies a reviewed operation. No repository .env is loaded. Omission means unmanaged. Never share API keys, signed URLs or review contacts through logs.
